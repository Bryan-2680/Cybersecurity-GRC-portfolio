### How This Portfolio Is Structured
Each project lives in its own folder under `projects/`, containing a short summary and a full report. All scenarios are demonstrative — built to show the application of a method or framework, not drawn from real production systems (see Disclaimer).   

---

### Projects

#### 1. Incident Response – Integration Failure Case Study
Applied the NIST SP 800-61 incident-response lifecycle to a system integration failure affecting transaction processing between systems. Demonstrates structured
detection, elimination-based root-cause analysis along the message path, and the design of preventative controls to reduce recurrence.

---

#### 2. Access Control – Role-Based Risk Assessment
A risk-based assessment of a role-based environment, identifying excessive permissions and segregation of duties conflicts, with a worked example of an SoD conflict. Recommends governance and control improvements aligned with least privilege, NIST SP 800-53 AC-6, and ISO/IEC 27001 Annex A.

---

#### 3. Security Assessment – Small Enterprise Environment
A structured, risk-based assessment of a small business, scoring risks on likelihood × impact with the rationale behind each rating, and prioritising remediation (MFA and phishing awareness as the Critical risks). Mapped to the NIST Cybersecurity Framework and ISO/IEC 27001 principles.

---

#### 4. Vulnerability Assessment – Public-Facing Database Risk
A qualitative vulnerability assessment of a public-facing database, following NIST SP 800-30 methodology (threat source → threat event → vulnerability → likelihood → impact). Uses quantified likelihood × severity scoring and identifies public exposure as the single root cause, with defence-in-depth remediation.

---

#### 5. Linux Access Control Enforcement – File Permission Audit
A hands-on Linux exercise reviewing and remediating file/directory permissions to enforce least privilege at the command line (ls -la, chmod), including verification of the corrected state and an explanation of discretionary access control (DAC) vs RBAC.

---

#### 6. Security Log Analysis – Suspicious Activity Investigation
Used SQL to query authentication and access logs for suspicious patterns (failed-login spikes, off-hours logins, sensitive-resource access), interpreting results against a baseline. Maps to the NIST CSF Detect function and recommends SIEM-based centralised monitoring.
